# Hermes 用量统计实施计划

> 使用 superpowers:executing-plans 在当前专用 clone 内串行实施；用户已批准设计与连续执行，不提交 git commit。

**Goal:** 同一看板正确统计、筛选 Codex 请求与 Hermes 聚合用量。

**Architecture:** 独立 HermesSource 只读读取 SQLite，归一化聚合记录进入现有历史账本；source_kind 与 api_call_count 贯穿查询和前端。

**Tech Stack:** Python 3.14 / sqlite3 / unittest / 原生 JavaScript。

**Spec:** TASK-HERMES.md，以及本会话批准的设计和补充 A/B/C。

## 全局约束

- 不改既有夹具；最终失败名单与基线相同，6 failures + 2 errors。
- 不拆伪请求，不编造请求计时、上下文容量或父子关系。
- Hermes 只读 URI；源库 mtime/sha256 不变，WAL 测试不新增 sidecar。
- 所有新增功能先真实 RED，再最小实现，再 GREEN；记录命令与输出到 work。
- 不提交、不发布、不改真实 Hermes 数据；实际扫描写入 work 下独立历史库。
- 用户已要求连续执行，计划完成后直接实施；临时材料 work，保留审计记录供验收。

## Review Focus

- 多 profile 相同 session ID 隔离；测试两个临时 profile。
- 累计行发生修正时替换旧快照；测试调用数和 Token 更新、重扫不翻倍。
- 未知价格和有效自报费用分支；测试正值/零值/unknown 状态。
- 混合数据的请求级统计只取 Codex；测试直方图与总请求数各自口径。
- 数据源筛选贯穿 API、会话下钻与导出；HTTP 与前端运行测试验证。

## 任务与验收（每个编号任务 2–5 分钟，顺序执行）

每项步骤固定为：写对应测试 → 运行并记录预期功能缺失的 RED → 最小实现 → 运行 GREEN → 更新 work/hermes-progress.md。无提交步骤。

1. **路径与读取器** — 创建 hermes_source.py、tests/test_hermes.py。接口 HermesSource(path, timezone).read()、resolve_hermes_paths(path=None)。临时同结构库验证聚合映射、last_seen 本地归日、workspace 兜底、缺失库降级和 profiles 发现。命令 `python -m unittest tests.test_hermes.HermesSourceTests -v`。
2. **只读与 WAL** — 同上测试文件，验证源库扫描前后 st_mtime_ns 和 sha256 一致、无新 -wal/-shm；保留打开中的 WAL writer 验证已提交数据可见。为无 sidecar WAL 库采取安全读取策略，绝不 immutable 忽略实际 WAL。命令同任务 1。
3. **旧库迁移** — 修改 backend.py 的 _create_schema/_store_snapshot/usage_records；新增 source_kind 默认 codex、api_call_count 默认 1、Hermes 元字段。tests/test_hermes.py 的 HermesMigrationTests 构造无新增列旧库并验证旧数据和默认值。命令 `python -m unittest tests.test_hermes.HermesMigrationTests -v`。
4. **扫描接入与 watermark** — backend.py DashboardDB 增加 hermes_db 参数，scan 追加 _scan_hermes；水位保存在独立 hermes_sources 表，快照引用仍用现有 history_sources。HermesScanTests 验证首次导入、重复跳过、累计更新替换、跨 profile 隔离和源库缺失。命令 `python -m unittest tests.test_hermes.HermesScanTests -v`。
5. **加权查询与来源过滤** — backend.py _add_metrics/_fetch_rows/_filter_sql/dashboard/tasks/sessions/requests；HermesAggregationTests 验证单行 7 调用而非 1，各分组、计价覆盖率和会话计数相等，分页 total 为记录数另有 request_count。审计 COUNT、len(rows)、+=1。命令 `python -m unittest tests.test_hermes.HermesAggregationTests -v`。
6. **费用** — pricing.py 增加 aggregate 选项强制普通档；backend.py 存储自报对照与有效回退，重计价遵循相同口径。HermesPricingTests 验证长上下文聚合普通档、参考价优先、自报回退与无效零值未计价。命令 `python -m unittest tests.test_hermes.HermesPricingTests -v`。
7. **请求指标边界** — backend.py 直方图/百分位/速度样本仅 Codex，Hermes 请求级字段 NULL、能力与范围提示；任务分类不推导父子关系。HermesAggregationTests 增加纯 Hermes/混合测试。命令同任务 5。
8. **HTTP、CLI、导出** — backend.py API 参数、_common_options/main CSV/JSON、desktop.py 启动参数透传。HermesIntegrationTests 用 HTTP 实际筛选，并调用 CLI 导出校验加权值和数据源。命令 `python -m unittest tests.test_hermes.HermesIntegrationTests -v`。
9. **前端筛选** — web/index.html、app.js、analytics.js 增加 sourceKind 状态和 source_kind 查询参数，保持四页签与布局 ID；tests/frontend_hermes_harness.js + Python wrapper 验证实际事件与请求参数。命令 `python -m unittest tests.test_hermes_frontend -v`。
10. **前端语义与能力显示** — 同上文件及 dashboard.css；Hermes 聚合记录调用数、自报费用/状态、workspace 来源、请求指标原因；全部模式标明仅 Codex。运行同任务 9，覆盖切换恢复。
11. **文档与计数审计** — README.md 新增 Hermes 数据源，work/hermes-count-audit.md 逐个判定 COUNT/len(rows)/+=1 的实际语义，补充遗漏的行为测试并 RED/GREEN。
12. **整体验收** — 全量 `python -m unittest discover -s tests` 与基线比对失败 ID；只读扫描 D:/Hermes/state.db 到 work/hermes-live.sqlite3，输出聚合行数、加权调用数；提供真实 serve 命令及 HTTP 联动验证。任何名单漂移停止并报告。最终独立代码审查仅报告实质问题，修复仍遵循 RED/GREEN。
